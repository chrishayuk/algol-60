# The X1 dialect

`algol60 --x1` runs a program as the ALGOL 60 system of Dijkstra and
Zonneveld for the Electrologica X1 (Mathematical Centre, Amsterdam, 1960;
this is the version of about 1964) would have run it, as far as the
documents say. It is not an emulation of the X1.

## Sources

- **[KA03]** F. E. J. Kruseman Aretz, *The Dijkstra–Zonneveld ALGOL 60
  compiler for the Electrologica X1*, CWI note SEN-N0301, 2003. Section 1.3
  reproduces, in translation, the 23 "special properties of the
  MC-Algol-system" from the user manual of 12 December 1962; appendix A the
  compile-time and run-time stops; chapter 7 the library; appendix B
  Zonneveld's outer planets program.
- **[KA-X1X8]** F. E. J. Kruseman Aretz, *A comparison between the ALGOL 60
  implementations on the Electrologica X1 and the Electrologica X8*, CWI.
  Section 3.2: the representation of values. Section 3.3.3: the run-time
  code of the for statement.
- **x1algol.pas**, Kruseman Aretz's Pascal version of the compiler, which
  "for a range of ALGOL 60 programs produces exactly the same object code
  as the original" [KA03, 1.5]. Its name-list prefill gives the library
  names.
- **[X8-lib]** The provisional library manual of the *X8* system, section 7
  (in translation in sergev's `doc/library-procedures.md`). The only
  description found of `PRINT`, `FIXT`, `ABSFIXT`, `FLOT`, `TAB`, `SUM`
  and `EVEN`. The X8 system came from the same institute and kept the
  names, but it is not the X1's manual.
- **[sergev]** https://github.com/sergev/x1-algol-compiler (Apache-2.0):
  the Pascal compiler, a C translation of it with three of its bugs
  documented, and a simulator that runs the compiler's object code. The
  run-time routines of the X1 (the "complex") were never published, so
  the simulator's are a reconstruction of their own. It is built in
  `sources/sergev-x1/build` and run by `compare/run.sh`; see
  [`compare/README.md`](../compare/README.md).

"Property n" is the n-th special property of [KA03, 1.3]; "stop n" is a
stop of [KA03, appendix A].

## The manual's rules are not the compiler's checks

The first version of this dialect refused programs that broke the
manual's rules. That was a misreading. [KA03, 1.3]: "The greatest
shortcoming of the system, however, was the almost complete absence of
syntax checks"; the only grammatical check was for undeclared identifiers.
And programs that break the rules compile with the real compiler: in
sergev's examples, `beer`, `disarium`, `magic_square`, `mersenne` and
`whetstone` declare procedures before variables (property 15), `lisp` and
`pentomino` put `if` after `do` (property 12), and `bulls_and_cows` has
`then if`, which even the Report forbids.

So `--x1` accepts such programs, with a warning naming the property: the
manual forbade it, the compiler did not check, and what followed is not
known. The run-time stops of appendix A (integer capacity, an array with a
lower bound above its upper) remain errors, since they really did stop the
X1.

## What changes the meaning of a program

| | The Report | The X1 | Source | Test (`tests/x1.rs`) |
| --- | --- | --- | --- | --- |
| The step of `for V := A step B until C` | Evaluated twice each time round, after `V := A` | Once each time round, and the first time *before* `V := A` | Property 11; FOR1, FOR5–FOR7 in [KA-X1X8, 3.3.3] | `property_11_*` |
| `go to` an undefined switch designator | A dummy statement (4.3.5) | Undefined; here an error | Property 10 | `property_10_*` |
| `abs` | Real | The type of its argument | Property 6 | `property_6_*` |
| `sqrt`, `ln` of a negative number | Undefined | Of its absolute value | Property 6 | `property_6_*` |
| The value of a typed procedure | Converted to the declared type | "Determined by the arithmetic carried out this time" | Property 18 | `property_18_*` |
| Order of evaluating parameters called by value | Not fixed; left to right here | The order of the specifications | Property 22 | `property_22_*` |
| Identifiers | All characters count | The first nine | Property 3 | `property_3_*` |
| `0.0`, `0⏨5` | Real | Integer | Property 4 | `property_4_*` |
| Whole numbers above 67108863 | Integer | Real | Property 4 | `property_4_*` |
| Integers | 64 bits here | ±67108863; beyond is stop 1–1 | [KA-X1X8, 3.2] | `stop_1_1_*` |
| An array whose lower bound is above its upper | Has no elements | Stop 1–2 | Stop 1–2 | `stop_1_2_*` |
| Real variables, value parameters and constants | 53-bit mantissa | Rounded to 40 bits when stored; 52 on the stack. A real constant is two words of the constant list, like a variable, so `0.1` itself has 40 bits | [KA-X1X8, 3.2]; `look_for_constant` in x1algol.pas; the real compiler on x1sim | `reals_are_stored_*` |
| `if b then if c then S else T` | Not allowed | Accepted; `else` goes with the nearest `if` | [sergev] `bulls_and_cows` | `then_if_*` |

**Rounding of stored reals.** [KA-X1X8, 3.2] does not say whether storing
rounds or truncates. Rounding is used, and sergev's simulator agrees: its
`FIXT(4, 17, 9999/7)` prints `1428.42857142910361289`, which is 9999/7
rounded to 40 bits; truncated it would be `1428.42857142724…`.

## The manual's rules (warnings)

| Property | Warned about |
| --- | --- |
| 5 | A standard function (`abs` ... `entier`) called as a statement |
| 12 | A conditional statement straight after `do` |
| 13 | A parameter delimiter other than a comma, such as `) Order: (` |
| 15 | Declarations other than in the order scalars, arrays, switches, procedures; specifications other than scalars and strings, arrays, labels and switches, procedures |
| 17 | Bounds that are not integer numbers, for an `own` array or one in the outermost block |
| 19 | A formal parameter without a specification |
| 21 | A label in the value list |
| [KA03, ch. 7] | `abs`, `sign`, `sqrt`, `sin`, `cos`, `ln`, `exp`, `entier`, `read`, `print`, `TAB`, `NLCR`, `SPACE` as actual parameters: operators of the run-time complex, not procedures. [sergev] documents the compiler producing bad code for some of these |

Property 8, labels that begin with a digit, is an error: the real
compiler stops with a fatal error on `10:` (`compare/probes/numeric-label.a60`).
Property 23 (a value array has at most five subscripts) is an error at the
call. Not checked: properties 1, 2, 9, 16 and 20.

## The library

`read`, `print`, `TAB`, `NLCR`, `SPACE`, `stop`, `SUM`, `PRINTTEXT`, `FLOT`,
`FIXT`, `ABSFIXT` and `EVEN` (the prefill of the name list in x1algol.pas),
with the meanings of [X8-lib]:

- `print(x)`: `FIXT(13, 0, x)` and six spaces if x is a whole number below
  2⁴⁰, otherwise `FLOT(13, 3, x)`; 21 positions either way.
- `ABSFIXT(n, m, x)`: a space, |x| with n digits before the point and m
  after, leading zeros as spaces (the units zero too, unless m = 0), a
  space. `FIXT` puts the sign "instead of the space immediately preceding
  the first digit or the decimal point".
- `FLOT`: sign, point, mantissa between .1 and 1, ⏨, signed exponent. The
  X8's has three parameters (n, m, x). **The X1's has two**: Zonneveld's
  program calls `FLOT(12, x)`. Three exponent digits are assumed for it.
- `TAB` to the next multiple of 8 (at least 2 on), `SPACE(n)`, `NLCR`; a
  line of 144 positions, beyond which a new line is begun.
- `SUM(i, a, b, x)` and `EVEN(n)` as the manual declares them.

`XEEN`, which reads the operator's console, is not provided. The
procedures of the Modified Report (`outstring`, `outreal` ...) are kept so
that the same test programs run in both dialects; the X1 did not have
them.

## Compared with the real compiler on sergev's simulator

`compare/` runs 24 probe programs through `--x1` and through the real 1964
compiler on x1sim; [`compare/README.md`](../compare/README.md) has the
table, and says which results are decided by the compiler (and so are
evidence about the X1) and which by the run-time (two reconstructions).
In brief:

- **Confirmed by the real compiler**: value parameters evaluated in the
  order of specification (property 22), nine symbols of an identifier
  (property 3), `then if` with `else` on the nearest `if`, both operands
  of `∧` and `∨` evaluated, and programs that break the manual's rules
  compiling (properties 15 and 19; Knuth's program as printed gives −67).
- **Corrected after it**: numeric labels make the compiler fail, so `--x1`
  refuses them; real constants are stored in 40 bits, so `0.1 - 0.1`
  stored is 0.
- **Zonneveld's outer planets** through the real compiler: all 88 numbers
  printed agree with `--x1`.
- **The run-times disagree** on `abs` of an integer and `sqrt` of a
  negative number (x1sim against property 6, which `--x1` follows), and on
  rounding −2.5 to an integer (open).

Its 22 example programs were also run with `--x1` and compared with the
outputs its README and tests record:

- **The same values**: `man_or_boy` (−67), `disarium`, `magic_square`,
  `mersenne`, `perfect_numbers`, `palindromic_primes`, `sieve` (78498
  primes below a million), `steady_squares`, `sum`, `hanoi`, `hello`.
- **Zonneveld's outer planets** (`historical/jaz164.alg`, with sergev's
  input data): all 45 coordinates after integrating over 1000 days agree
  to the nine decimals printed. (One differed in the last digit until
  real constants were stored in 40 bits.)
- **`FIXT`, `ABSFIXT`, `FLOT`**: the digits of all of sergev's test cases
  agree, including those that show the 40-bit store. The last printed
  digit differs once, where sergev truncates and the manual says the
  number "is rounded exactly to the last decimal place".
- **Layout, where the two readings differ**:
  - `FIXT`: sergev puts the sign in the first column (`-  57`), here it is
    beside the first digit (`  -57`), as the manual's wording says.
  - `FIXT` with decimals: sergev keeps the units zero (`- 0.049534455`),
    here it is suppressed (`-.049534455`), as the manual says it is unless
    m = 0.
  - `print`: sergev's is a convenience (compact, several arguments); here
    it is the manual's 21-position layout.
- **Not run here**: programs using `PRSYM`, `RESYM` and `TIMEOFDAY`
  (sergev's library has them; the 1964 compiler's name list does not),
  `whetstone` (sergev's several-argument `print`), `sqrt_test` (an X8
  program, with the X8's `FLOT`), `bulls_and_cows` (a missing `;` that the
  real compiler let through), `pentomino` (needs its input).
- **Not modelled here**: reals beyond about 10³⁰⁸ (the X1's reach about
  10⁶⁰⁰, and sergev's tests use them), and the X1's negative zero (it used
  ones' complement; sergev's `FIXT(3, 0, -0.0)` prints `-  0`).

## Results so far

- **`evaluation-count`**: the step is evaluated 11 times on the X1, 21 by
  the Report, for ten times round.
- **`jensen`**: H(100) is 5.18737751763547 on the X1 and 5.18737751763962
  by the Report; the running sum is cut to 40 bits every time it is
  stored.
- **`man-or-boy-1964`**, Knuth's program as printed: its parameters `x1`
  ... `x5` are unspecified, against property 19. The real compiler
  accepts it anyway, and gives −67 (`compare/probes/man-or-boy-unspecified.a60`),
  as `--x1` does.
- **`x1-probes`** differs on every line: properties 11, 22, 18 and 3, and
  the 40-bit store.
- **Koster's jungle generator** (CWI software archive) uses `RANDOM`,
  `SETRANDOM` and `XEEN`, none in the 1964 library; it mentions "the world
  famous X8 Computer". With the three declared, it runs.

## Running the real thing

The compiler survives; the run-time complex does not, as far as is
public. [KA03, 1.6]: Kruseman Aretz "wrote an X1 emulator, typed in the
complex of run–time support routines, and was so able to rerun the X1
ALGOL 60 system", but published neither.

- **Van den Hove's thesis** (2019) has a chapter III in two parts,
  "Translating ALGOL 60 Programs" and "Executing ALGOL 60 Programs", on an
  ISO C version of the system reverse-engineered from its assembler, and
  an appendix G, "Getting and Using the System". Only the front matter,
  contents and appendices A and B are public (UvA DARE); the author holds
  the rest for a book. The address it gives for current information,
  http://www.fibonacci.org/GHE3, did not answer on 23 November 2026. If
  the C version includes the run-time complex, the rows of the first table
  can be checked against the original routines. The author is the person
  to ask.
- **sergev's simulator** is built and in use (`compare/`). It answers
  every question the compiler decides. For the run-time it is a second
  reconstruction, not the original.
